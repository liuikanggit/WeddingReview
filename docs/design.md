# 拾光笺 待做事项 / 技术债

## 待办

- 相册页缺少筛选（只看已批注 / 只看未批注），照片多时找起来不方便
- 标注不支持图层顺序调整（后画的永远在上层），也没有多选
- 画笔粗细固定，只能选颜色
- 导出 PDF 时把所有合成图一次性收集在内存里再交给 Rust，几百张的相册会占用较多内存；更稳的做法是逐张追加写入
- 未处理 HEIC 在部分系统上的解码兼容性（依赖 `image` crate 的支持程度，需实测）
- `.weddingreview/thumbnails/` 只增不减，原图删除后缩略图不会清理
- 未做 Windows 端验证：workflow 配好了，但没在真机上跑过界面
- macOS 包只有 ad-hoc 签名，没有 Apple 开发者证书签名与公证，对方首次打开要「右键 → 打开」。
  彻底免掉需要 99 美元/年的开发者账号；届时在 CI 里配 `APPLE_CERTIFICATE` 等 secrets 即可

## 已知取舍

- 编辑器默认显示 2000px 预览图，放大超过 100% 才换成原图：翻页流畅与细节可见的折中。若发现某些场景下 2000px 不够看清，把 `PREVIEW_MAX_DIM` 调大即可（代价是预热更慢、缓存更大）。
- `.weddingreview/previews/` 整册约占原图体积的 2%（41 张约 11MB），换来翻页无等待。

- 缩略图生成线程数限制在 2–4（不吃满所有核心）：牺牲一点速度换取生成期间整机不卡顿。
- 导出的合成图宽度上限 1800px：A4 上打印足够（>250dpi），避免按原图分辨率导致内存暴涨。
- 标注坐标存在固定的基准坐标系（最长边 1400px）而非原图坐标系：位置绝不随窗口/缩放漂移，代价是极端放大时标注线条精度受限于该基准。
